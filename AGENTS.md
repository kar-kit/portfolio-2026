## Dev workflow

- `frontend-web/`: npm (`package-lock.json` is the lockfile — don't switch package managers). `npm install`, `npm run dev`, `npm run build`, `npm run typecheck`, `npm run lint`.
- `backend-sanity/`: bun (`bun.lock` is the lockfile). `bun install`, `bun run dev`, `bun run build`, `bun run typecheck`.
- `npm run typecheck` in `frontend-web` runs `next typegen && tsc --noEmit`. Next.js 16 generates global `PageProps`/`LayoutProps` helper types (used in `app/layout.tsx`) during `next dev`/`next build`/`next typegen` — running bare `tsc` without that step first produces a false-positive `Cannot find name 'LayoutProps'` error. Always typegen first; don't "fix" that error by importing or redefining the type.

## Safety / organization notes

- No secrets or `.env*` files should ever be committed. Root `.gitignore` excludes `frontend-web/.env*` — verify this still covers any new env file locations if the structure changes (e.g. if `backend-sanity` gains its own env file).
- Keep each subproject on its own package manager (npm for `frontend-web`, bun for `backend-sanity`) — don't introduce a second lockfile for either.
- Run `npm run lint` and `npm run typecheck` in `frontend-web/` before every commit.
- **Photos**: iPhone originals carry GPS EXIF. Every image added to `public/` must go through `design-reference/photos/strip.swift` first; see `design-reference/README.md`.
- `frontend-web/AGENTS.md` and `frontend-web/CLAUDE.md` are auto-managed by Next.js itself (regenerated by `next dev` per its own comment in that file) — don't hand-edit their content, they get overwritten.
- Keep the root `README.md`'s Status section honest as work progresses — it's a build-in-public project, so "not built yet" is a valid, intended state to show, not something to paper over. Never mark something done that hasn't shipped.
