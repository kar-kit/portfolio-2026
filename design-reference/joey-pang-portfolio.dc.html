WebSprint

Freelance practice delivering full-stack sites and booking systems for small businesses, hosted on infrastructure I run and maintain.

Next.jsSanityVercelProxmoxCloudflare Tunnel
5
active client engagements
C Context

Founded early 2024, initially built for early-stage founders who needed a technical partner instead of managing freelancers or hiring a CTO. The market focus evolved over time: 2024 MVP builds for founders, then fixed-fee website builds with Sanity CMS and a monthly retainer for small businesses and trades, then in 2026 a productised offering for course sellers and photo/video studios bundling an AI assistant to replace the separate subscriptions they'd otherwise pay for.

The through-line: owner-operators with no in-house technical capacity who need someone else to fully own the technical side.

A AI workflow

An AI-generated design mockup gets turned into a developer feature spec by an AI agent, which I then review.

On a recent storefront build, that review caught a privacy error (a client's private legal name used across the site instead of the name she uses publicly), a wrong brand-name spelling carried into the domain and metadata, a missing page that had to be added to scope, and a feature that got cut because it didn't serve the client's actual goal. For outreach specifically, AI drafts every message but a human sends each one by hand.

S Architecture

Client sites deploy on Vercel with Sanity as the CMS. Self-hosted infrastructure exists separately, purely for AI inference: a homelab running Proxmox, with one VM dedicated to a locally-hosted LLM behind a passed-through GPU, reached via a Cloudflare Tunnel.

One shared model serves every client, told apart by system prompt and client-specific data, not separate infrastructure per client. Self-hosting exists because it removes per-token API costs, which is what makes a low monthly retainer with a bundled AI assistant actually profitable.

02 · AI engineering · research project

MemoAI

A final-year research project testing whether LLMs can lower the barrier to spaced-repetition study tools.

PythonFastAPIOllamapgvectorNext.js
C Context

Formally titled “Investigating How LLMs Can Reduce the Perceived Effort of Utilising Online Spaced-Repetition Tools to Lower the Barrier for Adoption Among University Students.”

Spaced repetition and active recall are proven to work, but adoption is low specifically because of the perceived effort of manually creating and maintaining flashcards, not disbelief in the method. Existing tools (Anki, Brainscape, Quizlet) require manual creation or CSV import, which just relocates the effort, and their AI features are paywalled and only refine existing cards rather than generate from raw lecture material.

A AI workflow

The backend mediates every LLM call. The frontend never talks to the model directly, only structured data crosses that boundary, tightening prompting and shrinking the hallucination surface.

An explicit 80/20 rule governs the design: the model completes about 80% of flashcard-deck generation, the remaining 20% is mandatory human verification before anything saves. Generated content lands in temporary draft entities, never the real saved data directly, so a hallucination corrupts a draft, never real study material. Full automation was considered and rejected for exactly this reason.

S Architecture

A single consolidated backend service rather than microservices: a deliberate trade-off for a solo dev on a fixed academic deadline. Web-first frontend.

E Evidence

A real, ethics-approved study with a counterbalanced design where participants did both manual and AI-assisted flashcard creation in alternating order to cancel out fatigue and order effects.

03 · Full-stack system · testing discipline

SticksNBoulders

A powerlifting coaching platform replacing RTS, the industry-standard tool most coaches use and most hate.

Next.jsReactTypeScriptVitestAppwrite
E Evidence
1,188

2
real users today · athlete + coach

Real users today: me and my actual coach. Near-term, his other five athletes; by end of year, hopefully three more coaches. Small number, but both current users are the actual target user. 1,188 automated tests is the clearest quantified evidence.

C Context

Most powerlifting coaches use RTS (Reactive Training Systems), priced for high-volume coaching businesses, so beginner coaches and athletes end up sharing accounts.

Before this existed, the athlete-side workflow was: get a program from RTS, log actual sets in a separate app (Strong, better mobile UI), manually send the coach videos and RPE notes over WhatsApp because RTS can't attach media to a set, then separately screenshot the workout into ChatGPT to estimate calories before logging it in Cronometer. Five tools for one training session. On the coaching side, custom exercise names break RTS's UI and have to be retyped in full every time. My own coach was ready to go back to Excel rather than keep paying for it.

A AI workflow

I don't vibe code. AI's job here is running this like a real project: phasing features, sorting what can happen concurrently from what's a trivial tweak, and flagging what needs my coach's input before I build it, since he's a real coach who'll actually use this.

For tests, I write the first edge-case example by hand, then have an agent extend that pattern across the rest in Vitest. I trust the model more on low-stakes, easily-checked changes; everything still goes through a PR on a dev→prod branch flow from past internships.

S Architecture

Self-hosted Appwrite on a repurposed gaming PC, not Firebase or Appwrite Cloud.

I don't know yet if this sees real scale, so a hard resource ceiling forces me to notice and fix inefficient functions instead of paying for more compute. If it takes off, moving to Appwrite Cloud is a data migration, not a backend rewrite.

A text-to-speech service was silently parking most of a shared GPU's memory, starving the LLM inference running alongside it down to CPU-bound at about 5 minutes per response. Moving TTS to CPU-only freed the GPU and dropped that to about 14 seconds.
